1. Project Overview
Commute Tracker is a lightweight real-time location sharing web app. When you press "Start Monitoring" on your phone, your live GPS coordinates are sent to a server and instantly displayed on a map that your mom can watch on her own device — no app install needed on either side.
Property
Value
App Name
Commute Tracker
Purpose
Real-time commute monitoring between sender and viewer
Users
2 — Sender (Rocky) and Viewer (Mom)
Platform
Web browser — works on mobile and desktop
Network
Requires internet connection on both sides
App Install
None — just a URL
How It Works
Rocky opens the Sender screen on his phone browser
Presses "Start Monitoring" — browser starts reading GPS every 5 seconds
Each GPS coordinate is sent to the Node.js server via WebSocket
Server instantly pushes the coordinate to Mom's viewer screen
Mom sees a live moving marker on the map — no refresh needed
Rocky presses "Stop" when he arrives — Mom sees status update

3. System Architecture
The app uses a hub-and-spoke WebSocket model. The Node server is the hub. Both your phone (sender) and mom's browser (viewer) connect to it as spokes.
📡  Data Flow (End-to-End)
  [Rocky's Phone Browser]
       ↓  watchPosition() fires every 5 sec
       ↓  socket.emit("location", { lat, lng, timestamp })
       ↓
  [Node.js Server on Railway]
       ↓  Receives event → stores last known position in memory
       ↓  io.to(roomId).emit("location-update", data)
       ↓
  [Mom's Browser — Viewer Screen]
       ↓  socket.on("location-update") fires
       ↓  marker.setLatLng([lat, lng]) → map.panTo()
       ↓  polyline updated → timestamp label updated
3.1 Room-Based Isolation
To keep your location private, both the sender and viewer join a named Socket.io "room" using a shared secret code. Nobody outside that room receives the location data.
Concept
Details
Room ID
A short random code generated when monitoring starts (e.g. "rocky-abc123")
Sender URL
https://your-app.up.railway.app/sender
Viewer URL
https://your-app.up.railway.app/viewer?room=rocky-abc123
Sharing
Rocky copies the viewer URL and sends it to mom via WhatsApp — one tap to open

5. Key Code Logic
You do not need to memorise all of this — it is here so you understand what each piece does before you write it.
5.1 Sender — GPS Watch
SenderPage.jsx — Start Monitoring button logic
  const watchId = navigator.geolocation.watchPosition(
    (position) => {
      const { latitude, longitude, accuracy } = position.coords;
      socket.emit('location', { lat: latitude, lng: longitude, ts: Date.now() });
    },
    (error) => console.error('GPS error:', error),
    { enableHighAccuracy: true, maximumAge: 5000, timeout: 10000 }
  );
  // On Stop: navigator.geolocation.clearWatch(watchId);
5.2 Server — Broadcast Location
server/index.js — Socket.io event handler
  io.on('connection', (socket) => {
    socket.on('join-room', (roomId) => {
      socket.join(roomId);
    });
    socket.on('location', (data) => {
      const { roomId, lat, lng, ts } = data;
      lastKnown[roomId] = { lat, lng, ts };         // store in memory
      io.to(roomId).emit('location-update', { lat, lng, ts });  // push to viewers
    });
    socket.on('disconnect', () => { /* cleanup */ });
  });
5.3 Viewer — Live Map Update
ViewerPage.jsx — Socket listener + Leaflet update
  socket.on('location-update', ({ lat, lng, ts }) => {
    if (!markerRef.current) {
      markerRef.current = L.marker([lat, lng]).addTo(map);
    } else {
      markerRef.current.setLatLng([lat, lng]);
    }
    map.panTo([lat, lng]);
    trailPoints.push([lat, lng]);
    polylineRef.current.setLatLngs(trailPoints);
    setLastSeen(new Date(ts).toLocaleTimeString());
  });

8.2 Deployment Strategy — Two Options
Option A — All-in-One on Railway (Recommended for simplicity)
  Node server serves the React build files directly.
  One Railway project, one URL, zero CORS config needed.
  Build step: cd client && npm run build
  Server serves: app.use(express.static("client/dist"))
  Result: https://commute-tracker.up.railway.app/
          /sender → Sender screen
          /viewer → Viewer screen
Option B — Split Deploy (Railway backend + Vercel frontend)
  Backend: https://commute-tracker-api.up.railway.app  (Node + Socket.io)
  Frontend: https://commute-tracker.vercel.app          (React build)
  Requires CORS config on the server and env variable for API URL.
  Use this if you want Vercel's instant global CDN for the frontend.

10. Known Limitations & Solutions
Limitation
Notes / Workaround
GPS accuracy in buildings
Browser GPS uses towers + WiFi — may drift indoors. Acceptable for commute use.
iOS background GPS
Safari stops GPS when screen locks. Tell Rocky to keep screen on during commute.
No data persistence
Location history is in-memory — restarts wipe it. Add Redis later if needed.
Single sender per room
One sender per room in V1. Multi-sender needs room schema changes.
Railway free tier sleep
Railway's free plan has limits — upgrade to $5/month hobby plan if needed.
No auth / login
Security is a random room code. Good enough for personal use between two people.
