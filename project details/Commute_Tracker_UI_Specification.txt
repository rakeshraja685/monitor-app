    setLastCoords({ lat, lng });

8.1 iOS / Android Specific Notes
Important Mobile Gotchas
  iOS Safari: GPS (watchPosition) pauses when the screen locks or the tab goes to background.
  Fix: Add a banner on SenderPage — "Keep your screen on while monitoring is active."
  Android Chrome: GPS works in background tabs but may throttle after a few minutes.
  Fix: Battery saver toggle gives a manual workaround (30s intervals use less power).
  Both: HTTPS is required for the Geolocation API. Railway gives HTTPS by default — no issue.
  Safari on iOS: Geolocation permission prompt appears on first click only.
  Fix: Trigger watchPosition inside the button click handler, not on page load.
9. Error & Edge Case UI
Every error state needs a UI response. Define them here so nothing is left as a blank screen.
Error / Edge Case
Screen
UI Response
GPS permission denied
Sender
Show red banner — "Location permission denied. Please enable in browser settings." — disable Start button
GPS timeout
Sender
Show orange banner — "GPS signal lost. Retrying..." — keep isMonitoring true, retry watchPosition
Socket disconnected
Both
ConnectionChip turns red — Sender queues last location and re-emits on reconnect — Viewer shows "Reconnecting..."
Room not found
Viewer
Show full-screen card — "Room not found or expired. Ask Rocky to share a new link."
No GPS on device
Sender
On page load check navigator.geolocation — if undefined, show error — "GPS not available in this browser."
Viewer joins late
Viewer
Server sends last-known event on join — map pre-fills with Rocky's last position automatically
Low accuracy GPS
Sender
GPS accuracy chip turns red if > 50m — show tooltip "Move to open area for better accuracy"
